01 — The Problem

Two people.
One purchase.
No safe way to pay.

😰

Buyer A goes first

Sends their share, then waits. If Buyer B or the seller disappears — the money is gone. No recourse.

🤷

Buyer B goes first

Same problem, reversed. Someone always has to go first and absorb all the risk. It's a trust deadlock.

🏦

Use a middleman

Escrow services charge fees, require identity verification, and introduce a new party you still have to trust.

03 — Contract Design

The logic,
in SimplicityHL

// DuoPay — Joint Purchase Escrow
// Two co-buyers fund a contract.
// Seller is paid only when BOTH confirm.

contract DuoPay {
  // ── Parties ───────────────────────────────
  param buyer_a_pubkey: PubKey,
  param buyer_b_pubkey: PubKey,
  param seller_pubkey:  PubKey,

  // ── Amounts (L-BTC satoshis) ──────────────
  param buyer_a_amount: u64,
  param buyer_b_amount: u64,

  // ── Timeout block height ──────────────────
  param timeout_height: u32,

  // SPEND PATH 1: Both confirm → pay seller
  fn release(sig_a: Sig, sig_b: Sig) -> bool {
    verify_sig(buyer_a_pubkey, sig_a) &&
    verify_sig(buyer_b_pubkey, sig_b) &&
    output_value(0) == buyer_a_amount + buyer_b_amount &&
    output_pubkey(0) == seller_pubkey
  }

  // SPEND PATH 2: Timeout → refund both buyers
  fn refund(sig_a: Sig, sig_b: Sig) -> bool {
    current_block_height() >= timeout_height &&
    verify_sig(buyer_a_pubkey, sig_a) &&
    verify_sig(buyer_b_pubkey, sig_b) &&
    output_value(0) == buyer_a_amount &&
    output_pubkey(0) == buyer_a_pubkey &&
    output_value(1) == buyer_b_amount &&
    output_pubkey(1) == buyer_b_pubkey
  }
}

04 — Why Simplicity

Not just any chain.
Specifically this one.

01

No Surprise Failures

Simplicity has no loops and no unbounded recursion. The contract has exactly two outcomes: release or refund. Nothing can fail unexpectedly at runtime — both buyers can verify this before depositing a single satoshi.

02

Formally Verifiable

Both buyers can mathematically prove no unauthorized spend path exists in the contract. This is impossible on Ethereum. With DuoPay, the code IS the guarantee — not a promise from a company.

03

UTXO = No Global Risk

Each DuoPay contract is an isolated UTXO. A bug in another contract cannot drain yours. The reentrancy attacks that have stolen hundreds of millions on Ethereum are structurally impossible here.

04

Predictable Fees

Every Simplicity contract has a statically bounded execution cost. Before locking funds, both buyers know the exact fee. No gas estimation, no surprises, no failed transactions eating money.
