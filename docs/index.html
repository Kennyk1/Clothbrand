01 — The Problem

Two people.
One purchase.
No safe way to pay.

Buyer A goes first

Sends their share, then waits. If Buyer B or the seller disappears — the money is gone. No recourse.

Buyer B goes first

Same problem, reversed. Someone always absorbs all the risk. A trust deadlock with no exit.

Use a middleman

Escrow services charge fees, require identity checks, and add a third party you still have to trust.

03 — Contract Design

The logic,
in SimplicityHL

// DuoPay — Joint Purchase Escrow
// Seller paid only when BOTH buyers confirm.

contract DuoPay {
  // ── Parties ────────────────────────
  param buyer_a_pubkey: PubKey,
  param buyer_b_pubkey: PubKey,
  param seller_pubkey:  PubKey,

  // ── Amounts (L-BTC satoshis) ────────
  param buyer_a_amount: u64,
  param buyer_b_amount: u64,
  param timeout_height: u32,

  // SPEND PATH 1: Both confirm → pay seller
  fn release(sig_a: Sig, sig_b: Sig) -> bool {
    verify_sig(buyer_a_pubkey, sig_a) &&
    verify_sig(buyer_b_pubkey, sig_b) &&
    output_value(0) == buyer_a_amount + buyer_b_amount &&
    output_pubkey(0) == seller_pubkey
  }

  // SPEND PATH 2: Timeout → refund both
  fn refund(sig_a: Sig, sig_b: Sig) -> bool {
    current_block_height() >= timeout_height &&
    verify_sig(buyer_a_pubkey, sig_a) &&
    verify_sig(buyer_b_pubkey, sig_b) &&
    output_value(0) == buyer_a_amount &&
    output_pubkey(0) == buyer_a_pubkey &&
    output_value(1) == buyer_b_amount &&
    output_pubkey(1) == buyer_b_pubkey
  }
}

04 — Why Simplicity

Not just any chain.
Specifically this one.

01

No Surprise Failures

No loops, no unbounded recursion. Exactly two outcomes: release or refund. Both buyers verify this before depositing a single satoshi.

02

Formally Verifiable

Both parties can prove no unauthorized spend path exists. The code IS the guarantee — not a company's promise or a terms of service.

03

UTXO = No Global Risk

Each DuoPay contract is an isolated UTXO. Bugs in other contracts cannot touch yours. Reentrancy attacks are impossible by design.

04

Predictable Fees

Statically bounded execution cost. Both buyers see the exact fee before locking funds. No gas estimation games, no surprises.

05 — The Vision

This is just
the beginning.

DuoPay is designed to become a full trustless payment platform — eliminating the security risks of WhatsApp, Telegram, and TikTok payments entirely. Every money transfer verified on-chain. Every deal sealed with code, not promises.

Deal Links

Create a deal, share a link. The other party sees terms verified on-chain and deposits. No screenshots. No "trust me." The blockchain is the receipt.

Built-in Deal Chat

Every deal has its own chat room. Text, voice, video, PDF, documents — all in one place. No WhatsApp needed to coordinate a payment.

Deal Dashboard

Create, track, and manage deals in a clean interface. Deposit status verified in real time on-chain — no edited screenshots possible.

Trust Score

Every completed deal builds your on-chain reputation. Not required — but it elevates users who consistently deliver. Trust earned, not claimed.
